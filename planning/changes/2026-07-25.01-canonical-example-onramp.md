# Design: Canonical minimal-DI example (aiogram rollout)

## Summary

Ship a canonical, runnable example in `modern-di-aiogram`: a minimal
`examples/` bot wiring one `Settings` (APP scope) and one `GreetingService`
(REQUEST scope) into a message handler via the real `@inject` + `FromDI`
idiom, an in-memory smoke test that proves it runs, and the README
`Usage example:` line. This follows the locked pattern piloted in
`modern-di-faststream` (`planning/changes/2026-07-24.01-canonical-example-onramp.md`
in that repo): `examples/app.py` + `examples/__init__.py`, a smoke test that
covers the example to 100% with no coverage exclusion, and one README line.

## Motivation

The faststream pilot locked a reusable shape and flagged rollout to the other
`@inject`/`FromDI` integrations as a follow-up. `modern-di-aiogram` had no
`examples/` directory and no README `Usage example:` link, only the inline
`## Usage` snippet — the same D2/D6 gap the pilot's motivating audit found
across the integrations.

## Design

**The example** — `examples/app.py` (+ `examples/__init__.py`): the smallest
runnable aiogram bot demonstrating the recommended wiring, as a complete
program:

- `Settings` — `providers.Factory(scope=Scope.APP, creator=Settings)`,
  matching the README's `Settings` name.
- `GreetingService` — `providers.Factory(scope=Scope.REQUEST, ...)`, depends
  on `Settings` by type (auto-injected), added on top of the README's inline
  snippet to match the faststream-locked Settings+Service shape.
- one `@dispatcher.message()` handler decorated with `@inject`, taking the
  service via `typing.Annotated[GreetingService, FromDI(Dependencies.service)]`,
  wired by `setup_di(dispatcher, container)`. The handler answers with
  `service.greet(name)` built from the injected service, mirroring the
  README's `message.answer(...)` shape.
- `dispatcher.message()` is registered before any startup event fires
  (module-level, at import time), consistent with the repo's
  `auto_inject=True` ordering rule even though this example uses explicit
  `@inject` (order-independent, but kept consistent for readers).
- explicit `@inject` (not `auto_inject=True`): matches the README's primary
  documented idiom and keeps the example correct regardless of registration
  order.
- a `# Run for real (needs a real bot token): BOT_TOKEN=<token> python -m
  examples.app` header states the real-run requirement; the `_run()` +
  `if __name__ == "__main__":` boot lines are marked `# pragma: no cover`
  (unreachable in tests), per the pilot's stated rule for repos whose example
  has a standalone boot line.

**Smoke test** — `tests/test_example.py`: imports the example's `dispatcher`,
and using the repo's existing in-memory idiom (the `bot` fixture from
`tests/conftest.py`, `dispatcher.feed_update(...)`, and
`tests/factories.make_message_update`, all already used by
`tests/test_inject.py`/`tests/test_auto_inject.py`) feeds one fake `Update`
through the real dispatcher and asserts the real `GreetingService` output.
The only test double is the aiogram transport: `Bot.__call__` is monkeypatched
to capture the outgoing `SendMessage.text` instead of performing a real
Telegram API call — DI resolution, the handler, and `GreetingService.greet`
all run for real.

**Coverage** — none excluded except the two `# pragma: no cover` boot lines
noted above. The smoke test executes `examples/app.py` end to end (import
wires the dispatcher + handler; `feed_update` runs the handler), so the
example is measured under the repo's `--cov-fail-under=100` gate.

**README** — insert `Usage example: [examples/](./examples)` directly under
the `Full guide` line, before `## Installation`, matching the faststream
placement. The existing inline `## Usage` snippet stays; the example is its
fuller, runnable superset.

**Lint** — add `"CPY001", # no per-file copyright header` to
`[tool.ruff.lint] ignore`, matching the pilot (no per-file copyright headers
on the new example files).

No `modern_di_aiogram/` source changes, so no `architecture/` promotion —
this adds documentation-grade example + test, not a capability change.

## Non-goals

- `modern_di_aiogram.dialog` — the base handler idiom only; the dialog
  submodule has its own test tooling (`aiogram_dialog.test_tools`) and is out
  of scope here.
- A realistic/DB-backed starter — minimal DI demo only.
- New runtime dependencies — the example uses only `aiogram` + `modern-di`,
  already present.
- Editing the inline README snippet or any integration behavior.

## Testing

- `just test-ci` green: the smoke test covers `examples/app.py` to 100%
  (excluding the two pragma-marked boot lines) and asserts a real
  `GreetingService.greet(...)` result reached through the dispatcher, not a
  mock.
- `uvx ruff@0.16.0 check --no-fix .` and `uvx ruff@0.16.0 format --check .`
  green (CI floats to a newer ruff than the repo's pinned dev version).
- `just check-planning` and `just lint-ci` green.
- Manual sanity: `BOT_TOKEN=<token> python -m examples.app` starts polling
  against a real bot (documented, not a CI gate).

## Risk

- **Example rot** (low x low) — mitigated structurally: the example is
  measured (no coverage exclusion beyond the two boot lines) and the smoke
  test executes it every CI run.
- **Transport double masks a real regression** (low x low) — only
  `Bot.__call__` (the outgoing Telegram API call) is a double; the DI
  container, `@inject`, `FromDI`, and `GreetingService` all run for real, so a
  wiring regression still fails the assertion on `sent["text"]`.
